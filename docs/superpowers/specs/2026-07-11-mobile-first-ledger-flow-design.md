# 手机优先快速记账闭环设计

**日期：** 2026-07-11

**状态：** 已批准

**唯一开发面：** `http://localhost:3000`

**唯一主验收尺寸：** Android `390 × 844`

## 1. 目标

在不创建第二套移动客户端、不改变后端数据模型的前提下，把现有 Next.js 应用做成一个可在手机尺寸完整使用的最小成品。第一阶段只证明一条高频闭环：

`同意协议 → 登录 → 首页 → 记一笔 → 确认 → 新流水出现`

本阶段的判断标准不是“所有页面都适配过”，而是用户可以只用手机完成一次真实记账，过程没有页面溢出、导航遮挡、键盘遮挡、运行时错误或数据不同步。

## 2. 范围边界

### 包含

- Android `390 × 844` 下的协议确认、登录、首页入口、快速记账和流水确认。
- 手机顶栏、底部主导航以及“更多”入口。
- 复用现有自然语言记账解析器和手工创建流水表单。
- 创建成功后的 SWR 数据刷新、成功反馈和流水可见性。
- `1440 × 900` 桌面回归，确保现有侧边栏和业务页面不被破坏。

### 不包含

- Capacitor、Android Studio、APK/AAB、HTTPS 测试环境或商店发布。
- iOS 专项适配、原生插件、通知、生物识别、相机或离线同步。
- 资产、负债、目标、分类等页面的完整手机重绘。
- Prisma schema、认证协议、Server Action 边界或 API 路由改造。
- 桌面端视觉优化。

## 3. 设计决策

采用“核心流程纵切”，不做全站逐页修补，也不先重写全局响应式 CSS。实现仍然只有一套 Next.js 页面和业务逻辑：

- 桌面端继续使用现有侧边栏。
- `767px` 以下切换为手机导航和手机布局。
- 快速记账继续调用现有 `createTransaction` Server Action。
- Capacitor 后续只负责包装已经验收完成的手机 Web，不参与本阶段开发。

这样可以避免在成品前再次出现 Web、Android、iOS 三个界面同时演进。

## 4. 手机信息架构

### 底部主导航

底部固定保留五个高频入口：

1. 首页：`/`
2. 资产：`/management/assets`
3. 记一笔：`/management/ledger?focus=create`
4. 流水：`/management/ledger`
5. 预算：`/management/budget`

“记一笔”是视觉主操作，但仍是普通链接，不引入原生悬浮按钮或独立路由。

### 顶栏“更多”

当前顶栏分散的主题、修改密码和退出按钮合并到“更多”菜单；菜单同时提供：

- 负债管理
- 目标管理
- 分类管理
- 切换主题
- 修改密码
- 退出登录

菜单必须可通过再次点击、点击遮罩或按 `Escape` 关闭。桌面侧边栏保持原样。

### 安全区与内容空间

- 顶栏和底栏继续使用 `env(safe-area-inset-*)`。
- 主内容底部留白必须覆盖底部导航总高度。
- 页面本身不得出现横向滚动；只有明确的表格容器可以横向滚动。
- 交互控件的可点击区域不小于 `44 × 44px`。

## 5. 快速记账交互

### 入口

点击底部“记一笔”进入 `/management/ledger?focus=create`，强制激活流水标签，并把快速输入放在首屏可见区域。

### 输入与确认

复用现有 `LedgerAgentQuickEntry` 和 `buildLedgerAgentDraft`：

1. 用户输入一句自然语言，例如“今天午饭 32 用现金”。
2. 本地解析器生成草稿，不依赖 AI API Key 或外部网络。
3. `LedgerAgentQuickEntry.onApply` 将草稿映射进现有 `LedgerManager.formValues`。
4. 页面滚动并聚焦到创建表单；用户可以检查和修正类型、金额、币种、分类、账户、日期及备注。
5. 用户点击现有提交按钮后，由 `handleCreate` 调用 `createTransaction`。

快速入口只负责“生成并填充草稿”，不绕过现有手工表单直接写库。这样既复用当前校验和错误处理，也保留用户最终确认权。

### 成功状态

创建成功后：

- 通过父级控制的重置信号清空快速输入和创建表单；只有服务端确认成功后才重置。
- 显示明确的“已记账”成功反馈。
- 重新验证 `transactions`、`assets`、`budgets*` 和 `forecast*` 相关 SWR 缓存。
- 新流水无需整页刷新即可出现在流水列表中。

## 6. 数据流

```text
底部“记一笔”
  → /management/ledger?focus=create
  → LedgerAgentQuickEntry
  → buildLedgerAgentDraft（本地解析）
  → LedgerManager.formValues（人工检查）
  → handleCreate
  → createTransaction（Server Action）
  → PostgreSQL/Prisma
  → SWR mutate
  → 成功提示 + 新流水出现
```

本阶段不增加新的 API、数据库表或客户端持久化层。

## 7. 错误处理

| 场景 | 用户可见行为 |
|---|---|
| 自然语言无法解析 | 快速输入下显示具体错误，不修改当前表单 |
| 分类或账户无法唯一匹配 | 草稿保留金额和日期，缺失字段留空并要求人工选择 |
| 创建流水失败 | 保留已填表单，显示服务端错误，允许重试 |
| 会话密钥失效 | 沿用现有逻辑跳转 `/login` |
| 重复点击提交 | 提交期间禁用按钮，避免重复流水 |
| 登录 Server Action 异常 | 页面显示友好错误，不出现 Next.js Runtime Error 浮层 |
| 法律同意层拦截登录 | 先完成协议确认，再允许操作登录表单 |

## 8. 组件与文件边界

实施范围限定在以下现有边界：

| 文件 | 职责 |
|---|---|
| `src/components/layout/Sidebar.tsx` | 桌面侧边栏不变；拆出手机五项导航和“更多”菜单 |
| `src/app/globals.css` | 手机导航、安全区、遮罩、触控尺寸和溢出规则 |
| `src/app/management/ledger/LedgerManager.tsx` | 在手机 focus 流程中接入快速输入，并把草稿映射到现有表单 |
| `src/components/widgets/LedgerAgentQuickEntry.tsx` | 继续负责文本输入、解析结果和内联状态；不直接写库 |
| `src/lib/ledger-agent.ts` | 继续提供纯函数解析；不引入远程 AI 依赖 |
| `src/app/(auth)/login/page.tsx` | 只做手机可用性调整，不改变认证逻辑 |

当前工作树已有这些区域的未提交改动；实施时必须在现有内容之上做最小补丁，不覆盖或回退已有工作。

## 9. 验收标准

### 手机主流程：`390 × 844`

1. 打开 `/login`，协议确认层可完整阅读并关闭。
2. 无效账号显示页面内错误；页面没有 Runtime Error 浮层。
3. 使用审核账号登录后进入首页。
4. 底部导航始终为单行五项，不换行、不遮挡内容。
5. “更多”菜单可以打开、访问低频页面并可靠关闭。
6. 点击“记一笔”进入 focus 流程，输入框位于首屏。
7. 输入“今天午饭 32 用现金”可以生成草稿并填充表单。
8. 软键盘出现时，当前输入和最终提交按钮仍可到达。
9. 确认提交后显示成功反馈，新流水出现在列表中。
10. 页面宽度不超过 viewport；无意外横向滚动。
11. 控制台没有与本流程相关的 error/warn。

### 桌面回归：`1440 × 900`

1. 桌面侧边栏仍显示全部七个业务入口。
2. 手机顶栏、底栏和“更多”菜单不显示。
3. 登录和创建流水仍按现有方式工作。

## 10. 测试策略

- 单元测试：保留并扩展 `ledger-agent` 解析测试；为草稿到表单值的映射增加纯函数测试。
- 组件测试：验证手机主导航入口、active 状态和“更多”菜单的打开/关闭。
- 浏览器测试：使用 Playwright 固定 `390 × 844` 完成协议、登录、记账和流水出现的完整流程；再用 `390 × 520` 的缩短视口模拟软键盘占位，验证表单和提交按钮可以滚动到达。
- 回归测试：使用 `1440 × 900` 检查桌面侧边栏及现有表单。
- 视觉检查：首屏、键盘输入态、成功态分别截图；检查裁切、重叠、横向滚动和底栏遮挡。

浏览器自动化必须先接受法律同意层，再操作登录表单；不得用 `HEAD /login` 代替真实页面导航。

## 11. 实施顺序

1. 收敛手机导航并补齐“更多”菜单。
2. 在 ledger focus 流程中接入快速记账草稿填充。
3. 补齐成功、错误、键盘和滚动状态。
4. 添加单元/组件测试。
5. 用 Playwright 跑通手机闭环。
6. 做一次桌面回归，不扩展桌面视觉范围。

完成本规格后，下一里程碑才是部署 HTTPS 测试环境并在 Android 真机上复核，不在本轮提前展开。
