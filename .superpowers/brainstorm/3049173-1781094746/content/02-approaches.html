实施方案对比

三种实现路径 — 在 Tailwind v4 + Next.js 16 技术栈下

A

CSS 变量 + Tailwind 主题扩展（推荐）

在 globals.css 中用 @theme 扩展 Tailwind，定义 Firefly III 风格的色板。通过 data-theme 属性切换亮暗。保留所有 Tailwind 类名，改动最小。

优点

  • 改动最小，不破坏现有功能
  • 利用 Tailwind v4 原生 @theme 能力
  • 亮暗切换只需切换 data 属性
  • 所有组件自动响应主题

缺点

  • 需要在 globals.css 中维护较长的主题变量
B

CSS Modules 完全重写

为每个组件创建 .module.css 文件，用原生 CSS 变量控制主题。完全脱离 Tailwind 工具类。

优点

  • 完全控制样式细节
  • 组件样式隔离，无冲突

缺点

  • 工作量大，需重写所有组件的 className
  • 丢失 Tailwind 的响应式/变体便利性
  • 后续维护成本高
C

引入组件库 (shadcn/ui)

安装 shadcn/ui 或其他组件库，用预制组件替换现有 UI。主题切换由库内置支持。

优点

  • 开箱即用的组件和主题
  • 组件质量高，无障碍性好

缺点

  • 增加依赖，bundle 体积变大
  • 需要将现有功能映射到新组件
  • 可能与现有 echarts/自定义组件冲突
  • 风格可能不完全匹配 Firefly III

推荐方案 A 的核心思路

架构：CSS 变量 → Tailwind @theme → data-theme 切换
1. 主题 Token 层 — globals.css 定义 :root { --color-bg: #f4f6f9; ... } 和 [data-theme="dark"] { --color-bg: #0f172a; ... }
2. Tailwind 桥接 — @theme { --color-bg: var(--color-bg-ref); } 让 CSS 变量对接到 Tailwind 类名
3. 组件层 — 现有 bg-ledger-surface → bg-surface，自动跟随主题切换，无需逐个组件改
4. 主题切换 — ThemeProvider 组件 + localStorage 持久化，点击按钮切换 html 上的 data-theme
